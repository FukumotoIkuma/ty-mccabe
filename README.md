# ty-mccabe

**関数を分けても、分岐をほかの場所へ移しても下がらない McCabe の複雑度**を出す道具。呼ぶ先は [ty](https://github.com/astral-sh/ty) の答えで辿る。

> Astral の公式の道具ではない。ty（と ruff）の crate を組み込んで使っている。

## なぜ

関数ごとの複雑度（ruff の C901・flake8 の mccabe）は、関数を分けるだけで下がる。分岐を辞書・クラスの欄・コールバック・特殊メソッドに移しても下がる。しかし処理の複雑さは変わらない。「複雑度が閾値以上の関数には厳しいテストを書く」といった決まりは、閾値未満の小さな関数に分けるだけで外れられてしまう。

## 数え方

設計の全文は `docs/design.md`。

- **単位**は、関数（`def`）とモジュールの最上位（ty の意味の索引のスコープ）。クラスの本体・lambda・内包表記は、書いた単位の一部。関数の中に書いた関数は、外の関数と同じ組。
- 単位 u の複雑度 = u と、u から**閾値未満の単位だけを通って**辺を辿れる単位の、分岐の数の和 + 1。**閾値以上の単位**を呼ぶ所は 1 つの文（その先は数えない）で、閾値以上の単位はそれ自身の数で出る。呼び合う単位の組（再帰を含む）は、組を 1 つにまとめて数える。
- 分岐の数は ruff の C901（同じコミットの `ruff_linter` を組み込み、C901 だけを掛ける。`# noqa` は効かせない）。モジュールの最上位は、ruff の同じ数え方をモジュールの文に当てる。
- **辺は ty の答えだけ**で引く。ty の公開の関数と、可視性を上げるだけのパッチで呼べるようにした ty・ruff の関数を使い、ty の推論には手を入れない（`docs/design.md` の 9）。単位の中の次の位置で ty に定義を聞く。
  - 名前（定義への移動）。呼ぶ所に限らず、関数を値として書いた所（コールバック・表に入れた関数）も辺になる。
  - 属性（`ImplementationsFinder::for_attribute`。受け手の型の下位のクラスの上書きも。property は読む・書く・消すで getter・setter・deleter。クラスの本体で代入した関数・property も）。受け手が Protocol なら、ty が満たすと答えたクラスで継承の順で選ばれる同じ名前のメンバー（使う側で数える）。
  - 二項・単項の演算子（`definitions_for_bin_op`・`definitions_for_unary_op`）。
  - 呼び出し（`call_signature_details`。クラスならコンストラクタ、overload の関数なら実装も）。
  - クラスのパターン（`case C(x=1)` が読む属性。位置は ty が `__match_args__` などから答える）。
  - import（モジュールの最上位へ。`from m import *` は `__all__` のサブモジュールへ。モジュールからは親のパッケージへ）。
- **ty が答えない所は辺にしない**。比較・真偽の判定・`for`・`with`・添字・`+=`・`await` などが暗に呼ぶ特殊メソッド、組み込みの関数が中で呼ぶ特殊メソッド、記述子、metaclass の `__call__` が当たる。そこへ移した分岐は、使う側の数に入らない。限界の一覧は `docs/design.md` の 8。
- **分からない所**は出して、1 で終える。受け手の型を ty が Any・Unknown と答えた属性が当たる。

### 数を下げる方法

| 操作 | 数への効き方 |
|---|---|
| 分岐を減らす | 下がる |
| 閾値以上の単位を切り出す | 元の単位から切り出した分が抜ける。切り出した単位はそれ自身の数で出る |
| 閾値未満の関数・メソッドに分ける | 呼ぶ側へ展開されて元に戻る |
| 分岐を、ty が呼ぶ先を答えない所へ移す | 使う側から抜ける（`docs/design.md` の 8） |

## 入れ方

ty と同じ版を入れる（`ty-mccabe` の依存は `ty==<同じ版>`）。

```bash
uv add --dev ty-mccabe
```

## 使い方

```bash
ty-mccabe <ty のプロジェクトの根> <調べるディレクトリ>...          # 分からない所と数の要約（CI 向け）
ty-mccabe --list <ty のプロジェクトの根> <調べるディレクトリ>...   # 閾値以上の単位を大きい順に
ty-mccabe --all <ty のプロジェクトの根> <調べるディレクトリ>...    # すべての単位
ty-mccabe --explain 'pkg/a.py:12 run' <根> <ディレクトリ>...       # その単位の数に入れた単位と分岐の数
```

閾値は `--threshold <数>`（既定 10。ruff の C901 の既定と同じ）。ty のプロジェクトの根は、ty の設定（`pyproject.toml` の `[tool.ty]`・`ty.toml`）と仮想環境を読む所。例: `ty-mccabe --list . src`。

- 行の形: `複雑度<TAB>単位だけの複雑度（関数は ruff の C901 と同じ）<TAB>ファイル:行 クラス.関数`。モジュールの最上位の名前は `<module>`。
- 分からない所の行: `分からない（なぜ）: ファイル:行 属性の式（単位 の中）`。
- 終了コード: 分からない所が無ければ 0、あれば 1、道具が動けなければ（読めないファイル・読めないディレクトリ・構文の誤り・UTF-8 でない引数など）2。

## 版

版は ty と同じ（ty 0.0.103 なら 0.0.103）。道具だけを直して出し直すときは 4 桁目を足す（0.0.103.1）。

`.github/workflows/release.yml` が毎日、main の上で次をする（`scripts/follow_ty.py`）。

- ty の新しい版が出ていれば、その版の ty が指す ruff のコミットに合わせて書き換える。書式・clippy・テストが通れば main に積んで tag を打ち、PyPI に出す。通らなければ `follow-ty/<版>` の枝に置いて PR を開き、止める。その枝があるあいだは、人が直しているので上書きしない。
- 新しい版が無く、main の版のファイルが PyPI にそろっていなければ（前の公開が途中で落ちた）、その版の tag から作り直し、上がっていないファイルだけを出す。

tag を手で push して出すときも、書式・clippy・テストを通してから公開する。

## ビルド・テスト

ty・ruff の中の関数の可視性を上げるだけのパッチ（`patches/ty.patch`。`docs/design.md` の 9）を当てた ruff を、ビルドの前に `vendor/ruff` に用意する。

```bash
python scripts/prepare_ty.py     # Cargo.toml の rev の ruff を取ってきて、パッチを当てる
cargo test --release
```

パッチを直すときは、`vendor/ruff` で直してから `python scripts/prepare_ty.py save` で `patches/ty.patch` に書き出す。

- `tests/evade.rs`: 迂回の例（`tests/fixture/evade/`。分けた・辞書や欄に入れた・コールバックにした・特殊メソッドや Protocol の実装に移した・デコレータで登録した・別のモジュールに分けた・閾値以上の塊を切り出した・呼び合う組にした・名前を文字列で引いたなど）ごとに、行に書いた期待（関数の行の `# 期待 <数>`・`# 期待 分からない`、モジュールの最上位は `# <module> 期待 <数>`）と、閾値 8 で測った答えが同じこと。ty が答えないために本来の数にならない例は、期待の後ろに `限界 <今の数>（理由）` を書き、今の数と照らす（`docs/design.md` の 8）。
- `tests/smoke.rs`: 小さなプロジェクトでの数（呼ぶ先・下位のクラスの上書き・コンストラクタ・中に書いた関数）・閾値の効き方・終了コード・パスの出し方。
